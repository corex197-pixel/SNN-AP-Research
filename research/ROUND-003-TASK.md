## 六、评估状态隔离机制

### 6.1 理论背景

原始 ATLIF.forward 在 eval() 模式下仍会执行：

self.update_value += thre_updates / T

阈值更新函数在 optimizer.step() 后执行：

theta = theta + lr * update_value

update_value = 0

对于训练 Batch，手动更新信号近似为：

v_train = lambda_theta / T * sum_t(sum_b(mean_i(s[b,i,t]*g[b,i,t])))

其中：

g = max(1 - abs((m-theta)/theta), 0)

当验证期间产生累积量：

V_val = sum_k(v_val,k)

下一次训练可能执行：

theta_next = theta + Delta_theta_optimizer + lr*(v_train+V_val)

理想情况：

theta_next_ideal = theta + Delta_theta_optimizer + lr*v_train

本项目新增理论公式 R13：

Delta_theta_contamination = lr*V_val

R13 是独立推导，不是原论文定理。

代码已经支持这一潜在影响路径，但尚未测量正式训练中的实际污染规模。

### 6.2 实现要求

选择评估状态隔离方案，不直接改变原始 ATLIF 核心动力学。

实现独立评估上下文或包装器：

1. 进入评估前记录模型模式及相关内部状态。
2. 执行 eval 和 no_grad。
3. 收集需要的评估指标。
4. 评估结束后恢复原状态。
5. 异常退出时通过 finally 等机制保证恢复。

必须核查并处理：

- update_value
- r
- s
- act_value
- 阈值参数
- BN running statistics
- 网络内部可能存在的其他状态
- 每个模块原始 training/eval 标志
- 评估可能消耗的随机数状态

不得将 act_value 等张量错误地转换成不兼容类型，避免保留不必要的训练计算图。

如进入评估前存在非零 update_value，必须恢复原值，而不是简单清零。

评估指标应在恢复内部统计前提取。

原则：评估不应改变后续训练状态。

保留原始替代梯度 g²、硬重置、阈值更新函数及训练损失，不引入新剪枝算法。

### 6.3 对照实验

从相同模型参数、优化器状态和随机数状态出发，使用相同训练输入及标签构造：

A：不进行验证，直接执行训练步骤。

B：执行原始未隔离验证，再执行相同训练步骤。

C：执行隔离验证，再执行相同训练步骤。

优先使用 CPU 上的小型 ATLIF 网络完成机制测试，必要时在获准 GPU 上使用 ResNet-20 进行小规模工程测试。

记录：

- 评估前后 update_value。
- 每层实际阈值。
- 阈值更新差异。
- 网络权重差异。
- BN 状态差异。
- 优化器状态差异。
- 原始输出与隔离评估输出差异。
- 异常退出后的状态恢复。

定义：

D_theta_B = max_l(abs(theta_B[l]-theta_A[l]))

D_theta_C = max_l(abs(theta_C[l]-theta_A[l]))

对确定性 float32 测试，C与A应达到逐元素一致或预先记录的合理数值容差，默认绝对容差1e-5。

对接近零的差异同时保存实际绝对误差，不能只报告布尔通过状态。

B是否出现污染由实验决定，不要求必须出现预期差异。

如C与A不一致，首先检查随机状态、BN、训练模式、优化器状态、梯度和内部累积量。

此类实验属于工程机制验证，不检验 H-001、H-002。
